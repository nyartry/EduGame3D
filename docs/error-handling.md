# エラーハンドリングとTDD

TDDでは、失敗時の期待動作を先にテストへ書き、実装前にそのテストが失敗することを確かめます。修正後にテストを通し、その動作を維持しながら重複を整理します。テストを書くこと自体が重複を消すのではなく、共通化による動作の変化を検出できる状態にすることが目的です。

## このプロジェクトでの処理方針

| 場所 | 責任 |
| --- | --- |
| 低レベル処理 | 原因・操作・呼び出し位置を失わずに例外を伝える。`ThrowIfFailed` は HRESULT、操作名、ソース位置を例外へ含め、ここではログを出さない。 |
| シーン読み込み | 失敗したシーン名と処理段階を加えて一度記録する。準備・有効化に失敗した候補はRAIIで破棄し、元のシーンへ戻す。 |
| 画像読み込み | デコードに失敗した画像はパス・原因を一度記録し、代替画像を返す。成功したデコードだけを共有キャッシュへ登録し、失敗後の再試行を可能にする。 |
| アプリの起動境界 | 復旧されず到達した例外を記録・表示し、終了コード1で終了する。標準外の例外も受け止める。 |

初期シーンの同期読み込みが`false`を返した場合も、Launcherは`GetLastLoadError()`の原因を「Startup error」ダイアログに表示し、メインループへ入らず終了コード1を返します。この失敗はSceneManagerが記録済みなので、Launcherでは重ねてログを出しません。起動後のシーン切替では、従来どおり旧シーンを維持して再試行できます。

初期ロードの回帰テストは`SceneLifecycleTests::InitialLoadFailuresLeaveNoActiveSceneAndCanRetry`です。未登録、factory例外、null、Prepare例外、Activate例外について、原因・段階・ログ1件・失敗候補の破棄・再試行を確認します。これはSceneManagerのテストです。Launcherの画面と終了の確認は、`Game.cpp`の`InitialSceneName`だけを一時的に未登録名へ変えてGameAppをビルドし、リポジトリを作業ディレクトリとして起動して行います。確認後は名前を戻して再ビルドしてください。検証用の変更はコミットに含めません。

`DescribeException` は例外のメッセージ化だけを担当し、ログ出力や復旧方法は決めません。入れ子の原因も表示し、過度な深さや循環は16階層で打ち切ります。ゲーム固有の復旧方針をこの共通関数に入れないでください。

ログの出力先は `Diagnostics::SetSink` で交換できます。sink自体の例外は `Diagnostics::Write` が吸収します。画像キャッシュのロックはsinkの呼び出し前に解放するため、sinkから別の画像を読み込んでもロック待ちで停止しません。シーンの失敗通知が例外を投げた場合は、その通知エラーを別途記録して次のシーンへの通知を続け、元の読み込みエラーを維持します。

## 今回のテストと共通化

実装前に次の回帰テストが失敗することを確認してから修正しました。

- 非同期リクエストの登録時・ワーカー開始時にfactoryのコピーが例外を投げても、遷移を解除し、元のシーンを動かして再試行できる。
- 同期・非同期の準備失敗と有効化失敗には、シーン名・処理段階・元の原因が含まれ、ログが一件になる。
- 失敗通知先の一つが例外を投げても、ほかのシーンへ通知でき、元のエラーが置き換わらない。
- 画像の失敗は原因とパスを含む一件のログになる。画像を修復した後は、以前の代替画像を利用中でも再読み込みできる。
- 診断中に別の画像を読み込める。テストでは待機に上限を設け、旧実装でも停止せず失敗を検出する。
- HRESULTヘルパーは例外の情報を維持して、復旧側との二重記録を起こさない。

その後、シーンの生成・null確認・CPU準備を `PrepareScene` へまとめ、同期・非同期で共有しました。例外の種類ごとのメッセージ化を `DescribeException`、シーン名・処理段階の付与を `RecoverLoadException` へ集約しました。復旧動作は従来の `RecoverLoadFailure` へ集めています。

`DiagnosticsTests` は成功の HRESULT (`S_OK` / `S_FALSE`)、標準外の例外、入れ子の例外、空の例外、診断sinkの例外も検証します。`SceneLifecycleTests` と `AssetTests` の既存テストは、旧シーンの保持・GPU完了後の破棄・ワーカースレッドの担当・キャッシュ共有を引き続き検証します。

## 検証コマンド

リポジトリのルートから実行します。

```powershell
# Debug / Release、本体・エディター、全回帰テスト、WARP、シェーダー
.\tools\validate_core.ps1

# Debugに絞る場合
.\tools\validate_core.ps1 -Configurations Debug

# 画像読み込みとGPU共有のテストに絞る場合
.\tools\test_assets.ps1 -Configuration Debug -Gpu
```

`DiagnosticsTests.vcxproj` は既存の検証スクリプトから自動検出されます。

Visual Studioのテストエクスプローラーにも対応しています。追加した `VisualStudioTests` プロジェクトから同じテスト関数を個別実行・デバッグできます。登録は各テストファイル末尾の一覧でCLIと共有します。`validate_core.ps1` はネイティブテストも実行します。操作手順は [Visual Studioでテストを実行する](visual-studio-tests.md) を参照してください。

2026-09-08の検証では、Debug / Releaseの本体・エディター、全10種類のテスト、WARP GPUテスト、全4シェーダーのVS/PS、依存規則とプロジェクト登録の確認が成功しました。実行ログは `x64/error-handling-validation.log` に保存しています。ゲーム画面の手動操作や実機GPUの障害注入は実施していません。

## 今後変更するときの順序

1. 復旧方法を先に決める。代替データ、旧状態の維持、処理中止のどれが利用者に必要かを定義する。
2. 正常系に加え、失敗した戻り値・保持すべき状態・解放すべき資源・再試行・ログ件数をテストする。
3. テストが想定した理由で失敗したことを確認し、最小限の修正で通す。
4. 同じ責任を持つ処理だけを共通化する。画像の代替表示とシーンの復旧のように方針が異なる処理は、それぞれの境界に保つ。
5. 関係する回帰テストと本体ビルドを実行する。

失敗画像は明示的な次回の `Load` で再試行します。毎フレームの無制限な自動再試行は追加していません。成功済みの画像やGPUテクスチャを自動更新するホットリロードは、この変更の対象ではありません。また、メモリ枯渇時の完全な復旧、GPUデバイス喪失からの復元、シーンcommit中の外部資源解放サービスの例外安全性は、別途契約と故障注入テストが必要です。
