# エラー処理と診断

## このプロジェクトでの処理方針

| 場所 | 責任 |
| --- | --- |
| 低レベル処理 | 原因・操作・呼び出し位置を失わずに例外を伝える。`ThrowIfFailed` は HRESULT、操作名、ソース位置を例外へ含め、ここではログを出さない。 |
| シーン読み込み | 失敗したシーン名と処理段階を加えて一度記録する。準備・有効化に失敗した候補はRAIIで破棄し、元のシーンへ戻す。 |
| 画像読み込み | デコードに失敗した画像はパス・原因を一度記録し、代替画像を返す。成功したデコードだけを共有キャッシュへ登録し、失敗後の再試行を可能にする。 |
| アプリの起動境界 | 復旧されず到達した例外を記録・表示し、終了コード1で終了する。標準外の例外も受け止める。 |

初期シーンの同期読み込みが`false`を返した場合も、Launcherは`GetLastLoadError()`の原因を「Startup error」ダイアログに表示し、メインループへ入らず終了コード1を返します。この失敗はSceneManagerが記録済みなので、Launcherでは重ねてログを出しません。起動後のシーン切替では、旧シーンを維持して再試行できます。

`DescribeException` は例外のメッセージ化だけを担当し、ログ出力や復旧方法は決めません。入れ子の原因も表示し、過度な深さや循環は16階層で打ち切ります。ゲーム固有の復旧方針をこの共通関数に入れないでください。

ログの出力先は `Diagnostics::SetSink` で交換できます。sink自体の例外は `Diagnostics::Write` が吸収します。画像キャッシュのロックはsinkの呼び出し前に解放するため、sinkから別の画像を読み込んでもロック待ちで停止しません。シーンの失敗通知が例外を投げた場合は、その通知エラーを別途記録して次のシーンへの通知を続け、元の読み込みエラーを維持します。

非同期リクエストの登録時やワーカー開始時にfactoryのコピーが失敗した場合も、遷移を解除して旧シーンへ戻り、再試行できます。シーンの生成・null確認・CPU準備は `PrepareScene`、原因へのシーン名・処理段階の付与は `RecoverLoadException`、復旧は `RecoverLoadFailure` が担当します。

失敗画像は次回の `Load` で再試行します。代替画像を利用中でも、元の画像を修復してから再読み込みできます。毎フレームの自動再試行や、読み込み済みの画像・GPUテクスチャのホットリロードはありません。メモリ枯渇時の完全復旧や、GPUデバイス喪失からの復元も行いません。

## 検証コマンド

終了時のGPU待機・シーン解放・エディターの途中初期化については、[描画終了と資源の寿命](render-shutdown.md)を参照してください。解放失敗は個別に診断し、元の更新・描画エラーを維持したまま残りの解放を進めます。

リポジトリのルートから実行します。

```powershell
# Debug / Release、本体・エディター、全回帰テスト、WARP、シェーダー
.\tools\validate_core.ps1

# Debugに絞る場合
.\tools\validate_core.ps1 -Configurations Debug

# 画像読み込みとGPU共有のテストに絞る場合
.\tools\test_assets.ps1 -Configuration Debug -Gpu
```

主なテストは次のとおりです。

| テスト | 対象 |
| --- | --- |
| `DiagnosticsTests` | HRESULT、標準外・入れ子・空の例外、診断sinkの失敗。 |
| `SceneLifecycleTests` | 初期ロード・シーン切替の失敗、原因と段階、ログ1件、旧シーン保持、再試行、GPU完了後の破棄。 |
| `AssetTests` | 画像の失敗と再試行、診断中の別画像読み込み、キャッシュ共有。 |

Visual Studioのテストエクスプローラーでは、`VisualStudioTests` プロジェクトから同じテスト関数を個別実行・デバッグできます。操作手順は [Visual Studioでテストを実行する](visual-studio-tests.md) を参照してください。

## エラー処理を変更するとき

代替データ・旧状態の維持・処理中止のどれで復旧するかを決め、戻り値、保持する状態、資源解放、再試行、ログ件数をテストしてください。画像の代替表示とシーンの復旧は、それぞれの境界で扱います。シーン切替の確定処理へ外部資源の解放サービスを追加する場合は、その例外時の動作も定義して検証してください。
