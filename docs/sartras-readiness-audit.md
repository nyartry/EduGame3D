## 1. このプロジェクトについての判断

**プログラムの記述や解説資料が授業目的で公衆送信される場合には検討の余地があります。ただし、現在の構成を公開したり、学生がライブラリを使ったりするだけで補償金が発生するとは判断できません。**

2026年4月のSARTRAS利用報告手引きは、対象となり得る著作物にコンピュータプログラムの記述を含めています。一方、自分が創作し権利を持つ著作物を自分で送信する場合、一般公開サイトのURLを示すだけの場合、著作権法32条の引用に該当する場合は報告不要としています。[公式手引き・4、6～8頁](https://sartras.or.jp/wp-content/uploads/guide_to_filing_a_usage_report.pdf)

このため、最初に確定すべきなのは **①誰の著作物か、②誰がどの授業で何を送信するか、③どういう利用条件を付けるか** です。コードへの課金機能追加は、この制度の準備として挙げません。

| 想定する場面 | 今回の整理 |
|---|---|
| 権利者である本人が、自作コードを自分の授業で学生へ配信する | 上記の自己使用に該当する場合、本人の作品は利用報告の対象外。本人の授業だけを収入見込みの根拠にしない。 |
| 他の教員が、通常授業でコードや解説を教材に取り込みLMS等で学生へ送信する | 検討対象。公表済みの著作物、対象教育機関・授業、必要な範囲、第三者の権利、引用等の別規定や許諾との関係を確認する。 |
| 他の教員が、開発用ソフトとしてプロジェクト一式を学生へ配布する | コードを解説する教材利用と分けて判断する。ライブラリ全体の利用許諾をSARTRASが代行すると決めつけない。 |
| GitHubのURLを紹介し、学生がそこから入手して制作する | URLの紹介だけを報告対象としない。ダウンロード数やclone数を補償金算定用の利用件数へ読み替えない。 |

運用指針は、高等教育で市販ソフトを学生へ複製・送信することと、ソースコードを書面として配信することを区別しています。このライブラリへの適用は、利用実態と許諾条件を踏まえた個別判断が必要です。ソフトについては同指針14頁を参照。[運用指針](https://sartras.or.jp/unyoshishin-2/)

補償金は主に利用報告等に基づいて分配され、利用されても分配されない場合があります。現時点で年間収入・単価・開始時期を見積もる根拠はありません。[SARTRASの説明](https://sartras.or.jp/kyotsumokuteki/)

## 5. 利用実績と受領の準備

**問い合わせを終えるまで作業を止める必要はありません。** まず台帳と利用形態を整理します。具体的な判断が残る場合や自主申告の書式を取得する段階で、該当窓口へ確認するのが合理的です。

通常の分配は教育機関からの利用報告等を基に行われます。利用する教員へ正確な作品情報を渡し、学校の報告運用に合わせます。[分配の説明](https://sartras.or.jp/bunpai/)、[利用報告](https://sartras.or.jp/hokoku/)

加えて、**受託団体未定の権利者については、利用報告に載っていない作品でも、所定書式と証拠書類による自主申告を受ける規定があります。** このライブラリがその区分に該当するか、対象年度・書式・証拠の要件は未確認です。制度があることと、この作品の受給決定は区別します。[受託団体未定権利者補償金分配取扱規則・4条](https://sartras.or.jp/wp-content/uploads/jutakudantaimiteikenrishabunpai.pdf)

学校からの任意報告についても規定があります。権利者の自主申告と学校の任意報告は別の経路で、サンプル校の報告と同じ計算になるとは限りません。[分配規程実施細則・2条](https://sartras.or.jp/wp-content/uploads/bunpaikiteisaisoku.pdf)

記録する情報のひな型は以下です。これは内部の準備用で、SARTRASの公式提出書式ではありません。

| 項目 | 記録する内容 |
|---|---|
| 作品 | 正式名称、版／commit、権利者、公開／配布日、参照URL |
| 利用の主体 | 学校・授業担当者、通常授業か、自己使用か第三者利用か |
| 実際の行為 | 配信日、LMS・オンライン講義等の方法、受講対象、使用したファイル・節・分量 |

| 証拠 | 配信済み教材、授業案内、必要な範囲の配信記録、学校の確認資料など |
| 手続き | 学校の報告有無・対象期間、分配通知、照会結果、申告の受付・結果 |

個人情報を含む授業資料・契約・口座情報は公開リポジトリに置かず、必要な資料だけ別途管理します。学生氏名一覧や個々の端末の監視は、この準備に必要な機能として提案しません。

将来、権利者探索システムに自分の作品が載った場合は、該当する情報に基づいて受取申請できます。作品を自由に登録すれば分配される仕組みではありません。[MOTOMの説明](https://sartras.or.jp/motom/)

## 7. 次に着手する範囲と調査の限界

最初の作業単位は **権利台帳の未確認欄を埋め、公開できる最小の教材・ライブラリ構成を決めること（R01～R04）** です。特に、本人・学校の権利関係と、Mixamo／Nathan等の生素材を含む学生配布の可否を優先します。

本人の情報が必要なのは、(1)制作の職務上の位置づけと共同制作者、(2)外部コード・素材の入手元と取得時の条件、(3)想定する他の教員・授業での実利用、(4)公開名義と学生へ許可する行為です。現時点で未確認のまま権利者名や利用実績を推定して埋めていません。

今回の範囲は、追跡ファイルの棚卸し、権利表示の検索、代表的なコード・教材・ビルド設定の確認、素材のメタデータ、関連するGit履歴、および公式資料の照合です。全コードの独創性・類似性、過去の全ファイルの許諾、勤務先との契約、全バイナリの構成を確定した調査ではありません。未確認は違反認定ではありません。

この一覧を完了すれば公開・受領手続きの準備は進みますが、SARTRASから実際に補償金を得るには、対象となる利用・権利確認・分配決定が必要です。
